# 어댑터 정합

Franka 로 학습된 정책을 FR5 가 받아들이게 만드는 계층이다. 스케일, 관측, 상태
규약 셋을 맞춘다. **폐루프 성능으로 값을 쓸어보는 것은 마지막 수단이다.**

---

## 1. Franka 값을 그대로 쓰면 안 된다

같은 절차로 유도하되 값은 다르다.

| 항목 | Franka | FR5 | 비고 |
|---|---|---|---|
| `PSCALE` | 0.0245 | **0.0105** | 개루프에서 각각 유도 |
| `PXSC` / `PYSC` | 0.91 / 1.18 | **1.00 / 1.13** | |
| `QROT` | z180 | **ym90** | `grasp_link` 는 +x 접근, LIBERO EEF 는 +z |
| `EEFRAME` | right_gripper | **grasp_link** | |
| `ROTOFF` | 0 | **1** | 6축은 회전을 살리면 IK 교착 |
| `FLIP` / `WFLIP` | n / h | n / h | 같음 |
| 관절 수 | 7 | 6 | `J7OFF` 없음 |
| 그리퍼 단위 | 손가락 폭 (m) | 관절각 (rad) | 부등호가 뒤집힌다 |

---

## 2. 스케일 — 개루프 재생

### 왜 폐루프로 못 하나

Franka 에서는 실효 전달률이 `스케일 × 도달률` 인데 도달률 자체가 스케일의 함수라
역산이 수렴하지 않았다.

FR5 에서는 변위가 `PSCALE` 에 정확히 비례한다.

```
PSCALE     dx      dy      dz     변위/PSCALE (x)
0.008    +17.4   +17.4    +9.2    2175
0.012    +26.4   +26.0   +14.3    2200
0.016    +35.4   +34.5   +19.4    2213
0.020    +44.4   +43.1   +24.6    2220
```

6축이라 자세가 단순해 도달률 자기참조가 약한 것으로 보인다. 그래도 개루프를 쓰는
이유는 **폐루프에는 정책 출력과 관측 오차가 섞여 있기 때문**이다.

### 절차

참조 롤아웃(MuJoCo + Franka)의 액션 8행을 정책 호출 없이 어댑터에 투입하고
첫 질의(q0→q1)의 EE 변위를 축별로 잰다.

```
참조 (4 에피소드 평균)   dx +23.2   dy +25.8   dz +7.9 mm
FR5 (PSCALE=0.012)      dx +26.4   dy +26.0   dz +14.3 mm
축별 비                  x 1.14     y 1.01     z 1.81
```

비가 1.00 이 되는 값이 `PSCALE=0.0105  PXSC=1.00  PYSC=1.13` 이다.

**첫 질의만 쓴다.** q3 이후는 궤적이 벌어져 자코비안이 달라진다.

### z 는 보정하지 않았다

참조 dz 의 변동계수가 0.34 로 가장 크다(4.9~11.0 mm, 4 에피소드). 개루프 비 1.81 을
믿고 `PZSC` 를 낮추면 폐루프가 악화된다.

```
PZSC=1.00   task 8 tip-rim  −0.009  −0.009  −0.013
PZSC=0.75   task 8 tip-rim  −0.043  −0.032  −0.033
PZSC=0.63   task 8 tip-rim  −0.045  −0.045  −0.037
```

폐루프에서는 정책이 현재 z 를 보고 목표에 닿을 때까지 계속 명령한다. **스케일을
줄이면 목표에 못 닿아 오차가 남는다.** 개루프 비로 폐루프를 고칠 수 없다.

`PXSC` 도 마찬가지였다. 개루프 비 1.14 를 믿고 0.88 로 낮추자 task 5 의 정렬 오차가
67 mm 에서 85 mm 로 악화됐다.

## 3. 관측 — 정책 프로브

정책 서버에 동일 상태·동일 지시문으로 질의하고 **이미지만 교체**해 참조 액션과의
거리를 잰다. 로봇을 움직이지 않으므로 에피소드를 쓰지 않고 수 초에 끝난다.

```
조건                      참조거리   자체산포   (8회 반복)
참조 이미지 (기준선)        0.070     0.021
FR5 그대로                0.130     0.084
FR5 3인칭만 미러           0.105     0.085
FR5 손목만 미러            0.288     0.068
FR5 둘 다 미러             0.289     0.073
```

### 판정 기준

```
0.07 근처   기준선
0.08        정합.  FR5 팔이 화면에 찍히는 만큼의 차이
0.13        한쪽 채널 미러 문제
0.29        양쪽 뒤집힘
```

숫자만으로는 3인칭을 가리기 어렵다(0.130 대 0.105, 표준편차 0.048~0.084).
**설정을 보면 확정된다.**

```
씬 설정      flip_horizontal: true    3인칭을 1회 뒤집음
FLIP 기본값   "h"                      1회 더 → 원위치
WFLIP 기본값  ""                       손목은 아예 안 뒤집힘
```

Franka 는 `FLIP=n` 으로 씬에서만 1회 뒤집는다. FR5 도 같아야 한다.

`FLIP=n  WFLIP=h` 를 적용하자 폐루프 파지 오차가 y −140 mm 에서 −56 mm 로 줄었다.

### 정책 산포는 어댑터로 못 고친다

```
참조 이미지   자체산포 0.021
FR5 이미지    자체산포 0.068 ~ 0.085     3~4배
```

같은 이미지를 8번 질의해도 출력이 흩어진다. 미러를 어떻게 바꿔도 마찬가지다.
FR5 팔이 3인칭 화면에 찍히는 것이 학습 분포 밖이기 때문으로 보인다.

다중 샘플링은 일부만 완화한다.

```
          KSAMP=1   KSAMP=4   KSAMP=8
참조        0.076     0.062     0.064
FR5        0.108     0.097     0.082
```

FR5 는 0.108 → 0.082 로 24 % 줄지만 남는 0.018(기준선 0.064 대비)은 계통 편차라
더 안 줄어든다. 추론 비용이 8배이므로 벤치마크 본체에는 쓰지 않았다.

## 4. 상태 z

`ZOFF` 는 `grasp_link` 와 손가락 패드의 z 차이를 보정하는 값인데 **정책에 보내는
상태에도 적용된다.**

```
참조 초기 상태   x −0.2085   y  0.0000   z 1.17328
ZOFF=0.031      x −0.2121   y −0.0137   z 1.2034    z 가 30 mm 높음
ZOFF=0          x −0.2121   y −0.0137   z 1.1724    참조와 0.9 mm
```

파지 높이도 함께 맞는다.

```
ZOFF=0.031   tip-rim −0.043   테두리보다 43 mm 아래
ZOFF=0       tip-rim −0.006   테두리 높이
```

정책이 자기 높이를 30 mm 높게 알면 하강 명령이 달라지고 접근 궤적 전체가 틀어진다.

## 5. 그리퍼 환산

```python
GJ_OPEN, GJ_CLOSE = 0.0, 0.93   # AG-95 주 관절 (rad).  패드 109 mm <-> 16 mm
GW_OPEN = 0.04                  # 정책이 학습한 Franka 손가락 폭 (m)
NGRIP = 6                       # 주 관절 1 + mimic 5
```

선형 환산이다. 초기값은 참조 규약대로 `GINIT=0.0208` (Franka 손가락 폭의 절반)을 쓴다.

완전 개방 109 mm 로 물체 지름 112 mm 보다 좁다. 감싸는 파지가 불가능하고 테두리만
물 수 있다. **참조도 마찬가지이므로 이 자체는 정상이다.**

`GINIT` 을 0.04(완전 개방)로 두면 Franka 에서 정책 출력이 6배 흔들렸다. FR5 에서는
파지 오차 차이가 5 mm 로 작았으나, 참조 규약이므로 0.0208 을 쓴다.

## 6. 진단 순서

문제가 생기면 이 순서로 좁힌다.

```
1. 개루프 재생        축별 이동비.  스케일이 맞는지
2. 정책 프로브        참조 이미지 대비 액션 거리.  관측이 맞는지
3. 상태 로그          참조 초기 상태와 대조
4. 파지 로그          tip-rim, 정렬 오차 대 물체 반지름
5. 관절 로그          발산·해 분기
6. 판정 로그          네 조건 중 무엇이 막는지
```

폐루프로 파라미터를 쓸어보는 것은 이 여섯을 다 하고도 안 될 때다. `PYSC=3.0` 이
그 방법으로 나온 값이고, 태스크 0 에서만 맞았다.
