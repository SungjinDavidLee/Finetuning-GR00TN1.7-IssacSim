# 6축 고유 문제

Franka Panda 는 7축으로 여유자유도가 1 이다. FR5 는 6축이라 0 이다. 그 차이가
세 곳에서 드러난다.

---

## 1. 손목 관절 뒤집힘 → PhysX 발산

### 증상

```
[JD] s006  max 5.224   -0.143 +0.018 +0.086 +0.133 -5.224 +0.469
[JD] s007  max 8.090
     s007  max 57.942
     s007  max 78.260
     s007  max 574.349
     s007  max 13924.274
     s007  max 254266.879
     s007  max 3151244.078
```

5번 관절(wrist2)이 −5.224 rad = −299° 도는 해가 나온다. 그다음 지수적으로 발산해
관절각이 300만 rad 까지 간다. articulation 이 터지고 주변 물체가 수 m~수 km 날아간다.

### 원인

6축은 같은 EE 자세에 대한 해가 이산적이다. 팔꿈치 위/아래, 손목 뒤집힘 같은 분기에서
해가 바뀌면 관절이 크게 돈다. 7축은 여유자유도가 연속적으로 흡수한다.

`ROTOFF=1` 이라 자세 폴백이 `tgt_q` 하나뿐인 것도 겹친다. Franka 는 `tgt_q → QC → Q0`
셋을 시도해 되는 것을 고른다.

### 통계

```
ikfail > 0   3/8   발산 38%
ikfail = 0   2/40  발산  5%
             Fisher p = 0.027
```

다만 발산 5건 중 2건은 `ikfail=0` 이었다. IK 가 성공을 반환하면서 엉뚱한 해를 주는
경우가 있고 그것은 `ikfail` 로 안 잡힌다.

### 대책 — 관절 점프 제한

한 스텝 관절 변화가 `MAXJ` 를 넘는 해를 폐기하고 이전 자세를 유지한다.

```
MAXJ 미적용   관절 점프 로그 19줄,  발산 48판 중 5건 (10.4%)
MAXJ=0.5      관절 점프 로그  0줄,  발산 498판 중 0건
              Fisher p = 4.3 x 10^-6
```

`MAXJ=0.5` 는 정상 동작을 막지 않는다. 정상 판에서는 관절 변화가 0.15 rad 을
넘지 않는다.

**시험은 발산이 나는 태스크로 해야 한다.** 처음에 task 5·8 로 시험했는데 그 둘은
점프가 없어 세 조건이 전부 같게 나왔다. task 4 로 다시 하자 갈렸다.

### 물리 설정으로는 못 잡는다

| 시도 | 결과 |
|---|---|
| `physics_hz` 60 → 240 | 물체가 혼자 미끄러짐 (마찰이 60 Hz 기준) |
| `stabilizationThreshold=0` | 미끄러짐 |
| `contactOffset`/`restOffset` 변경 | 파묻힘 |
| 고정물에도 적용 | 서랍·손잡이가 혼자 회전 |
| 팔 토크 제한 | 중력 못 버팀. IK 실패 1164 |
| 그리퍼 토크 제한 | 100/30/10/3 전부 일관성 없음 |
| mimic 드라이브 해제 | 5/5 발산 |

## 2. 작업공간 — 서랍 안에 도달하지 못한다

### 증상

```
task 4   IK 실패 2638~2749 / 2800 행 (94~98%)
         작업공간 클램프 0/0/0/0
         파지 시도 22/50,  들기 9/50,  배치 0/50
```

**클램프가 0 이라는 것은 명령 위치가 범위 안이라는 뜻이다.** 위치는 닿는데
그 자세로는 해가 없다.

### 도달 한계 측정

정책을 끄고 팔만 21개 지점으로 보내 명령 대비 도달 오차를 쟀다.

| 거리 | 중앙선 오차 | 측면 ±0.12 m |
|---|---|---|
| 0.45 m | 1.41 mm | 1.5 mm |
| 0.55 m | 2.08 mm | 2.2 mm |
| 0.62 m | 2.80 mm | 70.85 mm |
| 0.68 m | 3.76 mm | 34.45 mm |
| 0.74 m | 5.35 mm | 34.53 mm |
| 0.80 m | 8.97 mm | IK 실패 |
| 0.86 m | IK 실패 | IK 실패 |

**측면으로 벗어나면 IK 가 성공을 반환하면서 엉뚱한 해를 준다.** 같은 거리에서
중앙선은 2.8~5.4 mm 인데 좌측은 34~71 mm 다.

서랍 안쪽은 깊고 좁아 측면 오프셋과 낮은 높이가 동시에 걸린다.

### Franka 와의 차이

Franka(7축)도 task 4 는 0/50 이다. 그러나 양상이 다르다.

```
Franka   서랍에서 꺼내는 것까지는 된다.  이송에서 실패
FR5      서랍 안 자세에 도달하지 못한다.  파지 시도 44%
```

## 3. 그리퍼 — 단위가 뒤집혀 판정이 무력화

AG-95 는 너클 관절 6개(주 1 + mimic 5)이고 값이 클수록 닫힌다. Franka 는
prismatic 손가락 폭이고 값이 클수록 열린다.

```python
_rop = joint_positions[-2] > REFOPEN    # Franka 기준
```

**부등호의 의미가 반대다.** 단위가 안 맞아 `REFOPEN=-1` 로 꺼두면 모든 값이
−1 보다 커서 항상 "열림"으로 통과한다. 물체를 쥔 채 접시 위에 있어도 해제로 판정된다.

관절각 문턱으로 바꿔야 한다. 손가락 8 mm 는 관절 0.744 rad 이다.

```
수정 전   open=1  1  1  1  1      항상 참
수정 후   open=0  0  1  0  0      해제 순간에만 1
```

### 파지력은 강성으로 못 올린다

```
GKP=10000    미끄러짐 0.108 ~ 0.176   발산 없음
GKP=30000    미끄러짐 0.226 ~ 0.981   악화
GKP=100000   PhysX 발산.  6판이 동일값
```

위치 제어 드라이브에서 kp 는 잡는 힘이 아니라 위치 오차에 비례하는 복원력이다.
올리면 힘이 아니라 튕김이 커진다.

`GCLOSE` 를 올려 덜 조이는 것도 역효과였다(들기 3/3 → 1/3).

마찰은 설정에 `static 5.0 / dynamic 4.0` 으로 이미 일반값의 다섯 배다.

## 4. 파지 게이트가 고정 높이 기준

6축 고유 문제는 아니지만 FR5 작업에서 드러났으므로 함께 적는다.

어댑터에는 "그리퍼가 일정 높이보다 위에 있으면 정책의 폐쇄 명령을 무시한다"는
게이트가 있다. 기본 문턱은 테이블 위 물체 기준의 고정값이다.

물체가 라메킨 위(z 0.939)에 있는 태스크에서는 닫아야 할 높이가 0.99 인데,
게이트가 0.945 까지 내려가야만 닫게 한다.

```
GZFRAC=0     개방 강제 126~206회,  tip-rim −0.034,  들기 0/3
GZFRAC=0.8   개방 강제      0회,  tip-rim −0.016,  들기 3/3
[GATE] obj z 0.9390 + 80% x 0.05265 -> GZMIN 0.9811
```

`GZFRAC` 는 물체의 실제 높이에서 문턱을 계산한다. 10태스크 중 5개가 높은 물체
(쿠키 상자 위, 라메킨 위, 스토브 위, 캐비닛 위, 서랍 안)다.

### 증상이 헷갈린다

게이트가 막으면 그리퍼가 테두리를 지나 몸통 중간에서 닫히고, 물체를 밀어내
받침에서 떨어뜨린 뒤 바닥에서 다시 잡는다. 육안으로는 "너무 깊이 들어간다"로 보이고,
로그에서는 `tip-rim` 이 −0.034 로 나온다.

z 스케일 문제로 오인하기 쉽다. `PZSC` 를 낮춰봤으나 정상 태스크만 망가졌다.
`개방 강제 횟수(govr)` 가 태스크마다 몇 배씩 다른 것이 판별 신호였다.
